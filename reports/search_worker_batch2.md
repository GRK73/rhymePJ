# 2차 작업: 연결 검색 Worker 이관

2026-09-20. 범위: P1의 한국어·영어 연결 계산 분리, DOM 없는 점수 함수, 취소·오류 복구. P0/P1 전체 및 검색 속도 개선 계획 전체는 아직 진행 중이다.

## 적용 결과

- `public/js/app.js`는 검색 조건을 읽어 요청을 만들고 진행 상태·결과를 표시한다. 기존처럼 한국어 surface 사전과 영어 사전 전체를 UI에서 순회하지 않는다.
- `public/js/search/linked-data.js`는 기존 사전/발음/의미/연결 보조 자산을 준비한다. `linked-candidates.js`와 `linked-core.js`가 기존 후보 정책과 점수식을 실행한다.
- `calculateScore()`와 경계 scorer는 자음·모음·세부 가중치를 인자로 받는다. 계산 함수 안에서 `document`나 slider를 읽지 않는다.
- `public/workers/linked-worker.js`는 필요한 정적 파일을 `/rhymePJ/` 기준 상대 경로에서 읽고 계산한다. 새 API·외부 모델·패키지를 추가하지 않았다.
- `linked-runtime.js`는 기존 단어 runtime과 동일한 `searchRhyme(request, {signal, onProgress})` 호출 형태를 사용한다. 실제 구현은 단어/연결 두 Worker다. 요청에는 주제·빈도·발음모드·세부 가중치·제외어·조사 허용이 포함된다.
- 화면의 활성 요청 토큰은 두 모드가 공유한다. 취소/새 요청/모드 전환 시 이전 연결 Worker를 종료하고 오래된 응답을 무시한다. 일반 연속 검색은 Worker를 재사용하며 오류·시간 초과 뒤에는 새 Worker로 복구한다.
- 진행 표시에는 실제 데이터 준비/계산 단계를 사용한다. 작업량을 모르는 연결 계산에 임의의 완료 퍼센트를 표시하지 않는다.

원본 V1/로컬 V2 스냅샷과 대형 연구 자료는 수정하지 않았다. GitHub push 및 Pages 배포는 수행하지 않았다.

## 결과 동등성

실제 브라우저 `handleSearch()`를 실행해 이전 로컬 V2와 비교했다. 입력 자산 해시·설정이 일치해야 통과하며 전체 결과의 단어·순서·점수·주요 메타데이터 해시와 Top-20을 비교한다.

| 검사 | 결과 | 보고서 (`reports/generated/`) |
|---|---|---|
| 기본 대표 8건: 단어/연결/한영/빈 입력/OOV | 8/8 동일 | `search-batch2-parity-basic.json` |
| 한국어/영어 연결 각 1개 × 기본 및 빈도·주제 0/5/10 | 20/20 동일 | `search-batch2-parity-weights.json` |
| 세부 가중치·주제·빈도·제외어·조사 허용 복합 | 2/2 동일 | `search-batch2-parity-detail.json` |
| 한국어 연결 20개 + 영어 연결 20개 | 40/40 동일 | `search-batch2-parity-broad.json` |

40개 확대 검사 ID는 `ko-linked-001`~`010`, `ko-linked-041`~`050`, `en-linked-001`~`020`이다. 각 비교 보고서에 원본/현재 캡처 파일 경로와 SHA-256이 있다. 위 검사 사이에는 중복 입력이 있으므로 70개 독립 질의의 검증이 아니다. 400개 전체와 전체 확장 프로필, 사람 품질 평가는 아직 미완료다.

## 화면 응답과 속도

실제 Node 정적 미리보기의 `/rhymePJ/`에서 Chrome 153.0.8010.48로 검사했다. Windows / Core 5 120U 환경이며 CPU·네트워크 제한은 적용하지 않았다.

`linked-worker-smoke-1789907406129.json`의 관측:

| 항목 | 관측 |
|---|---|
| 첫 주제 가중치 연결 검색 | 약 4,836ms, 결과 3,321개 |
| 검색 동안 20ms 화면 타이머 | 239회 실행, 최대 간격 64.8ms |
| 계산 단계에서 취소 | 약 0.3ms에 Promise 정리·Worker 종료·버튼 복구 |
| 없는 Worker 파일 → 정상 경로 재검색 | 오류 표시 후 3,321개 정상 복구 |
| 연속 검색 / 모드 전환 | 최신 검색 결과만 표시, 이전 상태 덮어쓰기 없음 |
| 검색 API 요청 | 0회 |

이 수치는 단일 데스크톱 smoke이며 p95·모바일 보장치가 아니다. 타이머 간격은 로딩과 결과 렌더링도 포함한다. Worker 계산을 중단하므로 UI가 전체 동기 순회가 끝날 때까지 기다리지 않는다는 점을 확인했다.

확대 40개 기본 입력을 각각 한 번 순차 실행한 표시 시간 중앙값:

| 결과 언어 | 변경 전 로컬 V2 | Worker 이관 후 |
|---|---:|---:|
| 한국어 20개 | 361ms | 400ms |
| 영어 20개 | 545ms | 531ms |

같은 입력 순서지만 반복 실험이 아니며 첫 데이터 로딩과 결과 없음 사례도 포함한다. 따라서 가속 배수나 p95로 해석하지 않는다. **이번 이관만으로 총 검색 시간이 개선됐다고 볼 수 없다.** 한국어 표본 중앙값은 오히려 늘었고, Worker의 데이터 준비·결과 전달 비용과 실행 환경 변동을 분리한 측정이 필요하다. 화면 응답과 계산량 감소는 별개의 과제다.

## 실행 검증

- `node scripts/check_project.js`: 통과.
- `node --test tests/search/*.test.mjs`: 14개 테스트 통과. 원본 음소 scorer와 72개 전역/세부/0 가중치 조합을 비교하는 테스트 포함.
- `python scripts/search/run_python_tests.py`: 18개 통과. 이번 환경에서는 설치된 Python의 절대 경로로 실행했다.
- `node scripts/validate_phonetic_search_pipeline.js --iterations=3 --stable-passes=3`: 3회 통과.
- `node scripts/validate_linked_search_pipeline.js --iterations=3 --stable-passes=3`: 60개 보조 사례 통과.
- `node scripts/v2/smoke_static_search_ui.js`: 단어 검색·진행 표시·모음/세부 가중치·취소 통과.
- `npm run smoke:linked-ui`에 해당하는 `node scripts/search/smoke_linked_ui.mjs`: 계산 중 응답·취소·오류 후 복구·연속 요청·모드 전환 통과.

현재 샌드박스에서 기본 `npm` 명령은 사용자 npm 경로를 찾지 못해 같은 Node 스크립트를 직접 실행했다. 실제 Chrome 및 설치된 Python 실행은 실행 권한 검토를 거쳐 수행했다. 테스트를 통과한 것으로 추정한 것이 아니라 각 실행 결과를 확인했다.

## 유지한 동작과 남은 작업

1. 연결 검색의 빈도 및 주제 점수식은 그대로다. 주제 slider가 0보다 큰 경우 고정 계수 0.15를 쓰는 기존 문제와 연결 검색의 발음모드가 실제 점수 경로에 반영되지 않는 기존 동작도 보존했다. 새 요청에 값을 담는 것과 점수에 적용하는 것은 다르다. 별도 점수 버전으로 수정해야 한다.
2. V2 단어 검색의 주제·빈도·수동 발음모드는 여전히 비활성이다. 따라서 해당 기능 복원이나 가중치를 포함한 단어 검색 가속을 완료했다고 주장하지 않는다.
3. 연결 계산은 동기 루프를 Worker에서 실행한다. 즉시 취소를 위해 Worker를 종료하므로 다음 요청의 데이터 준비가 다시 필요하다. 일반 검색에서는 캐시를 유지한다. 분할할 수 없는 입력만으로 캐시를 버리지 않도록 처리했다.
4. 기존 UI의 검색어 발음/세부 slider 계산 때문에 사전이 페이지와 연결 Worker 양쪽에 존재한다. 결과 목록도 기존 전체 결과를 복사해 반환한다. 전송·메모리·최초 로딩과 UI 렌더링을 더 줄여야 한다.
5. 다음은 고정 평가 범위 확장, 재사용 가능한 사전/발음 자료구조, 빌드 시 발음 계산 및 양쪽 경계 인덱스다. 후보 수를 임의로 줄이는 방식으로 속도를 맞추지 않는다.
6. 정적 파일로 동작하지만 Pages 공개 배포의 allowlist·자산 공급·외부 의존성 정리는 여전히 남아 있다. 최종 단일 Worker 구조, 전체 평가, 공개 배포를 완료한 상태는 아니다.
