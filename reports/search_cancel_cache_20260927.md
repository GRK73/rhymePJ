# 검색 취소·모드 전환 캐시 보존 수정

2026-09-27. 정상 취소까지 단어 Worker를 종료하던 이전 수정의 회귀를 바로잡았다.

## 변경

- 단어 검색 취소는 `cancel` 메시지를 보내는 협조적 취소로 변경했다. 호출자는 즉시 취소되고, 요청별 취소 확인을 기다리는 동안에도 준비된 Worker와 발음 레코드는 유지된다.
- 취소된 요청의 뒤늦은 진행·결과 메시지는 무시한다. 취소 확인이 5초 동안 오지 않는 경우에만 timeout으로 Worker를 종료한다. Worker 오류와 일반 요청 timeout의 종료·재생성은 유지한다.
- 공유 초기화 중 취소는 해당 호출자의 대기만 끝낸다. 초기화와 준비된 데이터는 새 검색이 이어받는다.
- 이미 끝난 요청에 늦게 도착한 Worker 취소 메시지는 무시하여 취소 ID가 계속 남지 않도록 했다.
- 연결 모드를 떠날 때 무조건 실행하던 `dispose()`를 제거했다. 실행 중인 연결 검색은 기존 abort 경로에서 Worker를 종료하지만, 유휴 Worker와 후보 캐시는 모드를 오갈 때 유지된다. 두 검색기를 사용하면 두 Worker의 데이터가 메모리에 남는 정책이다.
- 단어 표시·음소·발음 레이어 이름을 HTML 이스케이프했다. TTS의 인라인 `onclick` 문자열 조립을 없애고 이벤트 리스너로 원본 단어와 언어를 전달한다.
- 언어 또는 검색 모드 변경 시 이전 결과·더보기·결과 배열·의미 조회 관찰 상태를 지운다.
- 정적 단어 검색 자산을 제공하지 못하는 `start:legacy` 명령을 제거했다. 현재 앱은 `npm start`로 실행한다.

## 확인

- Node 검색 회귀 39개와 프로젝트 검사 통과. 정상 취소 후 Worker 재사용, 이전 요청의 늦은 메시지, 취소 미응답 timeout과 오류 복구를 검사했다.
- 실제 Chrome에서 취소 버튼·언어 변경·모드 변경·재검색을 각각 단어 검색의 재평가 단계에서 실행했다. 네 경우 모두 같은 Worker를 유지했고 후속 검색에 manifest/features/records 단계가 없었으며 50개 결과를 반환했다.
- 실제 Chrome에서 연결 검색 완료 후 단어 모드로 갔다가 돌아왔다. 같은 Worker와 후보 캐시를 사용했고 `candidate_cache_hit=1`, 한국어 결과 4,415개를 확인했다. 진행 중인 연결 검색의 모드 변경에서는 Worker가 종료되고 이전 결과가 표시되지 않았다.
- `<`, `>`, `&`, 따옴표, 역슬래시와 HTML 모양 문자열을 넣어 단어·음소·레이어가 그대로 표시되는지 검사했다. 추가 HTML 요소나 인라인 실행 속성이 생성되지 않았고, TTS에는 원본 문자열이 전달됐다.
- 브라우저 검사 명령: `node scripts/v2/smoke_static_search_ui.js`, `node scripts/search/smoke_linked_ui.mjs --source`.
- 연결 검사 기록: `reports/generated/linked-worker-smoke-1790500219266.json`.

이번 브라우저 검사는 병렬로 실행한 기능 검증이다. 표시 시간은 최적화 전후 속도 비교 근거로 사용하지 않는다. 데이터 재준비 여부와 Worker·후보 캐시의 유지 여부를 직접 확인했다.
