# 선택 로딩과 무손실 정적 자산 — opt3

2026-09-22. 화면의 전체 사전 선행 로딩을 없애고, 연결 Worker에는 선택한 언어의 사전과 주제 자료만 공급한다. 기존 후보·발음·점수·정렬 규칙을 유지하며 GitHub Pages에서 서버 연산 없이 실행한다.

## 변경 사항

- 화면은 전체 257,334행 사전을 내려받거나 보유하지 않는다. 한국어 검색어는 규칙과 작은 발음 보조 자료를 사용한다. 영어는 128개 발음 조각 중 하나만 읽으며 최근 조각 하나만 보관한다. 측정한 `time` 조각은 1,123행이다.
- 한국어 연결 Worker 사전에는 `word`, `lang`, `zipf`만 보존한다. 영어 사전은 발음과 결과 메타데이터를 포함한 원본 행 전체를 유지한다. 언어별 순서 및 중복 단어의 조회 규칙도 보존한다.
- 주제 자료는 선택한 언어의 벡터만 읽는다. 다른 언어가 주제를 알고 있는지만으로도 기존 필터가 활성화되는 경우가 있어, 반대 언어에서는 해당 주제의 작은 조각만 조회한다. 단어 검색이나 주제를 끈 연결 검색에서는 벡터 요청이 없다. 전체 언어 검색에서는 양쪽 자료를 준비한다.
- JSON을 빌드 시 gzip으로 압축하고 브라우저에서 해제한다. 벡터 양자화·반올림은 하지 않으며 `-0`까지 보존한다. 압축 바이트의 SHA-256과 길이를 읽을 때 검사한다.
- 자산 파일명에 내용 해시를 넣고 `force-cache`로 요청한다. manifest는 `no-cache`로 재검증한다. 실패하면 오류를 표시하고 재검색할 수 있다. Service Worker 오프라인 보장이나 이전 릴리스 자동 복구는 아직 구현하지 않았다.
- 연결 모드를 벗어나면 Worker를 종료해 자료를 해제한다. 발음 자료 준비 중 취소와 검색어 변경도 처리한다.

## 자산 규모

MB는 1,000,000바이트 기준이다. 파일 크기이며 JS 객체 힙 크기가 아니다.

| 자산 | JSON MB | gzip MB |
|---|---:|---:|
| 한국어 연결 사전의 필요한 필드 | 5.17 | 0.76 |
| 영어 연결 사전 | 15.33 | 2.05 |
| 한국어 의미 벡터 | 53.61 | 19.25 |
| 영어 의미 벡터 | 45.68 | 16.42 |
| 한국어 주 연결 자료 | 38.19 | 14.10 |
| 한국어 구어 연결 보조 자료 | 34.20 | 11.28 |

manifest는 압축 자산 397개를 참조하지만 한 검색에서 모두 요청하지 않는다. 주제 조각과 전체 벡터를 함께 배포하므로 생성 자산 전체는 약 106.9MB다. 이전 해시 파일은 자동 삭제하지 않는다. 공개 artifact에는 현재 manifest와 그 참조 파일만 포함해야 한다.

## 첫 검색 측정

비교 기준은 `tests/reference/opt2/`의 소스 25파일이다. Windows/Core 5 120U/Chrome 153, loopback HTTP에서 매번 새 프로필을 사용하고 각 설정·엔진을 3회 번갈아 실행한다. 준비용 검색 없이 페이지 준비부터 첫 검색 결과 표시까지 측정한다. 빈도=5, 주제 사용 시 주제=5다.

최종 코드 측정의 준비+첫 검색 중앙값:

서버가 응답한 데이터 바이트 × 요청 횟수이며 화면/Worker 중복 요청을 포함한다. 기존 JSON을 HTTP 압축하지 않는 비교 서버의 수치다. GitHub Pages의 전송 압축·캐시 조건과 같지 않으므로 실제 Pages 전송량 개선율로 일반화하지 않는다. 코드·이미지와 HTTP 헤더는 제외한다.

화면의 전체 사전 행 수는 모든 변경 후 실행에서 0이었다. 전체 프로세스 최대 메모리 감소율을 측정한 것은 아니다. Worker의 큰 한국어 pair 자료, 결과 객체, 사용한 언어의 의미 벡터 메모리는 남는다.

## 검증

- 전수 데이터 검사: 원본 파일 해시, 영어 사전 전체, 한국어 빈도 필드, 모든 발음 조각, 두 언어의 모든 벡터·주제 조각, 연결 보조 자료가 일치했다. `reports/generated/loading-assets-validation.json`.
- 실제 브라우저 가중치 20회: 기존 opt2와 결과 수·전체 점수·순서·표시 메타데이터 일치. `reports/generated/search-assets1-parity-weights.json`.
- 추가 14개 시나리오: 반대 언어 주제, 미등록 주제, 전체 언어, 한영 교차, 세부 가중치/제외어/조사, 단어 검색/OOV가 일치했다. `reports/generated/loading-modes-1790003700765.json`.
- 검색 Node 테스트 23개, 프로젝트 검사, 기존 음소 검사 1회 및 연결 검사 60건 통과. 정적 단어 UI와 연결 UI의 취소·복구·최신 요청 우선 처리도 확인했다.
- 최종 연결 UI 검사 `reports/generated/linked-worker-smoke-1790003862231.json`은 발음 자료 준비 중 즉시 취소와 변경된 검색어 무시까지 확인했다. 단일 실행의 최대 타이머 간격은 251.5ms로, 화면 지연이 완전히 사라졌다는 주장은 하지 않는다.

전체 400개 질의의 모든 가중치 조합과 사람 평가는 별도 과제다. 단어 모드의 주제/빈도 비활성 상태와 연결 주제 slider의 고정 계수는 유지한다.

## 실행과 재현

빌드·테스트는 Node.js 24를 사용한다. `JSON.rawJSON`으로 음수 0을 보존하며 Pages workflow의 Node 버전도 24로 맞췄다. 브라우저에는 `DecompressionStream('gzip')`과 HTTPS의 Web Crypto가 필요하다. Pages HTTPS 또는 localhost의 현대 브라우저에서 정적으로 실행하며 검색 API나 Python 서버는 사용하지 않는다.

```bash
npm run build:loading-assets
npm run validate:loading-assets
npm start
npm run benchmark:loading-assets
npm run check:loading-modes
npm run smoke:linked-ui
```

`npm start`는 원본/빌더가 바뀌었거나 자산이 누락되면 압축 자료를 재생성한다. 별도 서버로 `public/`을 제공할 때는 먼저 빌드 명령을 실행한다. 생성물 `public/assets/linked/v1/`는 Git에서 제외했다. 현재 원본 `public/data/model/` 자료와 기존 V2 단어 인덱스가 필요하다.

일반 `compare_reference.mjs`는 서로 다른 파일 형식을 동일 입력으로 허용하지 않는다. 이번에는 `compare_loading_reference.mjs`가 원본과 모든 파생 자료의 값 동등성 및 실제 소비한 파일 해시를 먼저 확인한 뒤 결과를 비교한다.

공개 Pages 업로드는 하지 않았다. 배포 allowlist/원본 출처 검토와 정적 artifact 공급은 기존 별도 작업으로 남아 있다. 큰 한국어 pair 자료를 검색 경계 인덱스로 분할하는 작업은 다음 단계다.
